Server slow hai? Linux troubleshooting cheat sheet

Check in this order: load → CPU → memory → disk → logs → service → network. Each step tells you what to run and what to look for.

Download PDF

1Is the server overloaded?

uptime
Shows the load average for the last 1, 5 and 15 minutes.
nproc
Number of CPU cores. Look for: load average higher than this number = more work than the server can handle.

2Which process is eating the CPU?

top
Live view of all processes. Press P to sort by CPU, M by memory, q to quit. (htop is easier if it's installed.)
ps aux --sort=-%cpu | head
Top 10 CPU-hungry processes. Look for: one process sitting near 100% CPU.

3Is memory (RAM) running out?

free -h
RAM and swap in GB/MB. Look for: "available" close to zero and swap filling up = the server is short of RAM.
ps aux --sort=-%mem | head
Top 10 processes by memory use.

4Is the disk full?

df -h
Space used on each disk/partition. Look for: anything at 90–100%. A full disk makes apps slow or crash.
sudo du -sh /var/log/* | sort -h
Which folders are biggest (here, logs). Change the path to check other folders.

5Is the disk too slow?

vmstat 1 5
5 readings, one per second. Look for: a high number in the wa column = CPU is waiting for the disk.
iostat -x 1 3
Per-disk detail (needs the sysstat package). Look for: %util close to 100.

6What do the logs say?

sudo journalctl -p err -b
All errors since the last boot.
sudo journalctl -u nginx --since "1 hour ago"
Logs of one service for the last hour (replace nginx with your service).
sudo tail -f /var/log/syslog
Watch the system log live (Ubuntu). If the file isn't there, use journalctl.
sudo dmesg -T | tail -20
Kernel messages. Look for: "Out of memory" = Linux killed a process to free RAM.

7Is the service actually running?

systemctl status nginx
Running, failed or restarting, plus its last few log lines.
systemctl --failed
Every service that has failed.

8Is it the network?

sudo ss -tulpn
Which ports are open and which process is listening on each.
curl -I http://localhost
Does the app answer from inside the server? Look for: 200 = fine, 5xx = the app has a problem.
ping -c 4 google.com
Can the server reach the internet, and how fast.

9Fix it (carefully)

sudo systemctl restart nginx
Restart the service that's stuck.
kill <PID>
Stop a runaway process (PID from top or ps). Use kill -9 <PID> only if it won't stop. Never kill a process you don't understand on a production server.

How to answer this in an interview

"First, I check the load with uptime. Then I use top to see which process is using the most CPU, free -h for memory and df -h for disk space. After that, I read the logs with journalctl and the application's own logs, check the service status with systemctl, and finally check the network."
